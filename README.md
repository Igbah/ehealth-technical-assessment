## Reproducing Part 1, Question 2

Run in order from the repository root. Each stage reads the previous stage's output; none of the intermediate steps can be skipped or reordered.

```bash
python Pipeline/q2_facility_access/01_clean.py
python Pipeline/q2_facility_access/02_load_db.py
python Pipeline/q2_facility_access/03_compute_access.py
python Pipeline/q2_facility_access/04_classify_gaps.py
python Pipeline/q2_facility_access/05_make_outputs.py
```

**Note on file paths:** each script currently has its input/output paths hardcoded in its `if __name__ == "__main__":` block, written for the original assessment machine's folder layout (`C:\Users\Administrator\Desktop\e-health_assessment\...`). To run elsewhere, update those paths at the bottom of each script to point at your local `Data/` and `Outputs/` folders — the functions themselves take paths as parameters, so only the `__main__` block needs editing.

**Outputs produced:** `facilities_clean.csv`, `reconciliation_log.csv`, `q2.duckdb` (the analytical database), `ward_accessibility.csv`, `facility_adequacy.csv`, `ward_gap_classification.csv`, `wards_accessibility.gpkg`, `ward_summary_table.csv`, `most_severe_gaps.csv`.

### The one manual step in Q2 — stated explicitly, per submission requirement #2

The final A3 cartographic map layout (symbology, legend design, page layout) was produced manually in ArcGIS Pro, using `wards_accessibility.gpkg` (the output of `05_make_outputs.py`) as the input layer. **This step is not automated, and was deliberately kept out of the pipeline.** Reason: ArcGIS Pro project files (`.aprx`) are tied to the licensed installation and project structure of the machine that created them, and are not portable or reproducible on an evaluator's machine without their own ArcGIS Pro license and manual re-creation of the layout regardless. Automating this would not have made the map more reproducible — it would only have made the *data* underlying the map (which is what actually needed to be reproducible) harder to audit, by hiding it behind a proprietary project file. All data the map is built from is fully reproducible via `05_make_outputs.py`; only the visual layout choices are manual.

## Reproducing Part 2, Question 4

```bash
python Pipeline/q4_coverage_survey/analyze_coverage.py
python Pipeline/q4_coverage_survey/interviewer_qa.py
```

These two scripts are independent of each other and of the Q2 pipeline — both read directly from `Data/Part2_Q4_Coverage_Survey/` and can be run in either order.

**Note on file paths:** same as Q2 above — update `DATA_DIR` (and the output path in `analyze_coverage.py`) at the top of each script for your local folder layout.

**Outputs produced:** `q4_analysis_dataset.csv` (the final weighted, deduplicated child-level analysis dataset), plus printed console output containing all reported statistics (weighted coverage estimates, design effects, effective sample sizes, interviewer-level diagnostics).

No manual steps are required for Q4 — it runs fully end to end from raw CSVs to final statistics.
